# Taste
- Before starting a task, prefers to first search for and install an existing skill/tool that solves it deterministically, then do the work with it. Confidence: 0.8
- When a tool or skill is chosen, expects the reasoning behind the choice plus the original source links (repo/skill page) so he can research and verify it himself. Confidence: 0.6
- Prefers skills installed globally (`~/.agents/skills`, available to the agent in any project) rather than project-local copies, avoiding duplication per repo. Confidence: 0.5
- When several design/direction options are on the table, wants the chosen option built out as a full-fidelity, interactive prototype (real copy, real design tokens, sized as it will ship) instead of a prose comparison of pros and cons — so he can judge it by looking at it before approving implementation. This includes deferring the real third-party integration (e.g. EmailJS) so the artifact only simulates its states. Confidence: 0.8
- Before writing a new section/feature, wants the reusable pieces of the whole project (shared components, utilities, tokens, conventions) identified first so the new code builds on them instead of reinventing locally. Confidence: 0.6
- Wants section interactions to be expressive and illustrative — something the visitor can actually see/touch — instead of a purely informational layout, and prefers them to surface the full inventory at a glance while letting interested visitors drill into per-item detail, rather than trimming content down to a summary. Confidence: 0.6
- In client-facing site copy, wants how he works described in plain, non-technical language (what the client brings, what he does, what they get) instead of naming frameworks/tools — that is where his way of seeing and handling each request should show. Confidence: 0.6
- Once a design has been approved, expects it to be live and visible immediately without extra setup: already-approved UI (e.g. the minimal contact form) must not be gated behind optional env vars/config that silently hide it — a fallback should degrade gracefully rather than replace the approved element. Confidence: 0.7
- Rejects decorative blocks that carry no information (e.g. a placeholder "0 ↗ 1" card): if a panel says nothing useful, remove it and let the real content fill the space. Confidence: 0.5
- In portfolio/experience content, wants each company described in a line or two (what the business actually did) so the reader has context before reading the role and achievements, rather than jumping straight to tasks. Confidence: 0.5
